A finalidade da ferramenta

O que o agents faz

O agents cria e atualiza arquivos de instruções para agentes de IA em um projeto.

A equipe escreve

As instruções dizem como o agente deve trabalhar: como escrever código, quais verificações fazer ou como descrever uma mudança.

O projeto configura

O projeto informa quais fontes usar e onde gravar os documentos em agents-compose.yml.

O agents prepara os arquivos

Ele reúne o conteúdo escolhido e gera os documentos que o agente vai consultar, começando por AGENTS.md.

AGENTS.md é o ponto de entrada das orientações do projeto. A equipe define as regras; o agents cuida de preparar e atualizar os arquivos.

O problema que a ferramenta resolve

Por que isso ajuda?

Quando vários projetos usam as mesmas orientações, manter cópias manualmente dá trabalho.

Sem uma origem compartilhada

Uma regra aparece no portal e na loja. Quando ela muda, alguém precisa lembrar de atualizar os dois lugares.

Com uma origem compartilhada

A equipe mantém o texto em um lugar. Cada projeto escolhe as instruções de que precisa e gera seus documentos pelo agents.

No consumidor · portal/agents-compose.yml

O projeto escolhe qual versão consumir

Depois de publicar a tag na base, configure o manifesto do portal. Endereço e versão abaixo são exemplos.

YAMLportal/agents-compose.yml · arquivo completo
schemaVersion: 2
agents:
  repository: https://git.example.com/equipe/instrucoes.git
  ref: v0.1.0
outputs:
  AGENTS.md:
    include:
      conventions:
        out_dir: docs/conventions
        local: {tpl_dir: templates/docs/conventions-local}
        remote: {tpl_dir: templates/docs/conventions}
        entries:
          - origin: remote
            from: commits.tpl.md
Vem da base

Da base vêm templates/AGENTS.tpl.md e commits.tpl.md. agents.ref fixa a tag.

Fica no portal

O contexto criado por init permanece em local.tpl_dir. As fontes locais entram automaticamente.

Vai ser gerado no portal

AGENTS.md e documentos em out_dir. Editar o manifesto ainda não gera esses arquivos.

init preserva o template principal local, mas esta composição usa o da base. Adotar outra tag exige editar agents.ref e gerar de novo.

No consumidor · terminal em portal/

Conferir o projeto sem gerar documentos

Use depois de editar o manifesto ou criar, copiar e alterar um template.

BASHExemplo: o contexto perdeu o bloco de leitura
agents validate
Saída resumida · Erro em contexto-do-projeto.tpl.md:
bloco AGENT-CARD ausente.
Código de saída: 2

Corrija a fonte e repita

Depois de corrigir o template, execute agents validate novamente. Com tudo válido, o comando termina com código 0.

O que é conferido

  • Node e os pré-requisitos necessários.
  • Manifesto, caminhos e integração.
  • Cabeçalhos e bloco AGENT-CARD.
  • Conflitos entre destinos de documentos.
BASHPara receber detalhes técnicos da falha
agents validate --debug

Git só é exigido para entradas Git. A validação preserva os arquivos do projeto e as tags.

Validate não corrige arquivos automaticamente. Para verificar se os documentos gerados estão atuais, use sync --check.

O pacote da CLI fornece esta skill. agents init a instala dentro do projeto consumidor.

└── .agents/

Pedido à IA no portal

“Atualize os documentos conforme o manifesto atual.”

O agente segue o roteiro

1. Lê agents-compose.yml e as fontes existentes, sem editá-los.

2. Chama a CLI dentro de portal/:

BASHTerminal em portal/
agents validate
agents sync --dry-run
agents sync
agents sync --check

3. Relata quais documentos mudaram e quais ficaram iguais. Se já estiverem atuais, nenhuma regravação.

Prévia termina sem aplicar. Erros são relatados sem editar regras ou configuração. Autoria usa agents-write-conventions; versão usa agents-update-version.

Referência dos quatro comandos

Todas as opções da CLI

--base

Em init, cria a base com AGENTS.md próprio e duas skills. Em validate, confere a base inicializada e o catálogo.

--starter minimal

Com init --base, acrescenta duas regras de exemplo. Sem a opção, o catálogo começa vazio.

--dry-run

Init mostra arquivos; sync mostra documentos; release mostra a próxima tag. A prévia preserva esses destinos.

--check

Em sync, retorna 0 se os documentos estão atuais ou 1 se há diferenças, sem gravá-los.

--bump minor

Em release, aceita patch, minor ou major. A CLI descobre a versão atual e calcula o número.

--repo-root DIRETÓRIO

Opcional: aponta para outro projeto. Dentro do projeto, basta usar o comando sem essa opção.

--json

Entrega resultados, mudanças e diagnósticos em formato estruturado para automações.

--debug

Acrescenta detalhes técnicos para investigar uma falha; não muda o resultado da validação.

--help

Mostra a ajuda geral ou de um comando, por exemplo agents sync --help.

--version

agents --version informa a versão da CLI; ela é independente da tag da base.

Init e release em prévia não gravam nada. Validate e sync com base Git podem preencher o cache. Saídas: 0 sucesso; 1 divergência no check; 2 uso, validação ou conflito; 3 falha operacional.
